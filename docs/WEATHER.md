# Optional weather for the packing checklist

In a **Trip-aware list**, enter the destination and trip dates, then use **Weather for your checklist**. Search sends only the place text you enter to the app server and Open-Meteo. Choose the exact returned city, region/country and timezone; nothing is selected automatically. **Retrieve forecast for this place** resolves that place ID again and requests daily minimum/maximum temperatures and maximum precipitation probability. The server sends coordinates and timezone, never trip dates, travellers, item records, photos or account credentials.

The retrieved forecast is an unsaved review until **Save forecast to this pack**. Review actual date coverage and missing values first. The copy retains the selected place, actual forecast-grid coordinates, timezone, original retrieval time, source link and response SHA-256. The grid can differ from the place coordinates. Source hashes identify bytes; they do not independently certify forecast accuracy or the authenticity of an imported copy.

Saved forecasts remain in ordinary/private metadata backups and explicit household copies. Household ID remapping never changes the provider's numeric place ID. Invalid records and hidden fields are refused by import/sharing validation. Explicitly removing saved weather leaves the existing checklist and saved packing progress unchanged. Editing a destination preserves the old source but pauses its suggestions. Packing-only sessions also pause weather suggestions and require no destination disclosure.

## Coverage and reminders

Only supplied daily rows overlapping the trip dates can inform reminders. A sixteen-day request is a provider request limit, not a promise that all trip dates or all values will be covered. Longer/future trips show uncovered dates; there is no climate or historical-weather substitution. A null value stays missing and cannot establish dry, warm or cold conditions. Dates and coverage use the selected place's timezone. Retrieved weather is paused after six hours, on an invalid future retrieval clock, on invalid/passed trip dates, or when no trip dates overlap. The interface rechecks age every minute. Offline access preserves the original retrieval time rather than making an old forecast fresh.

The current explainable thresholds are app packing heuristics: a supplied daily minimum at or below 10 °C suggests a warm layer; a maximum at or above 25 °C suggests light clothing; a precipitation probability at or above 40% suggests a rain layer. Every reminder states the covered part of the trip and stays optional. It does not add belongings or change required items, packed positions, assignments or solver constraints. **Add saved item** uses existing recorded geometry and properties. **Add details** opens the ordinary item editor so a new item is measured or scanned before entering the spatial plan. Reminders do not establish suitable clothing, medical needs, local conditions, hazard warnings or travel safety.

The saved source and coverage appear in the offline printable sequence. Settings can display forecast temperatures in Celsius or Fahrenheit without changing the saved Celsius values. Failed retrievals leave the saved source and original timestamp unchanged.

## Service configuration

Live weather is **off by default**. No provider subscription, key, paid request or deployment is provisioned by this feature. [Open-Meteo's terms](https://open-meteo.com/en/terms) distinguish noncommercial access from commercial product use. An operator must choose the appropriate existing entitlement:

- `WEATHER_ACCESS=off` is the default and returns an unavailable status without calling the provider.
- `WEATHER_ACCESS=noncommercial` uses the public endpoints only where the operator's use qualifies. Do not use this setting to bypass commercial access requirements.
- `WEATHER_ACCESS=commercial` requires an authorised existing server-side key in `WEATHER_API_KEY` or `WEATHER_API_KEY_FILE`; configure only one key source. The key file should be private and outside the checkout. Customer endpoints are fixed; credentials never enter the web bundle, returned forecast, source URL or error message.

The optional `deploy/compose.weather.yaml` overlay reads a Docker secret from `PACKING_WEATHER_KEY_FILE` and sets commercial access. It enables neither purchasing nor billing setup. Combine it with `deploy/compose.yaml` only after provider access and production HTTPS have been authorised and configured. Native builds require an exact HTTPS `VITE_WEATHER_API_ORIGIN` and an explicitly allowed native origin in `APP_ALLOWED_ORIGINS`. The saved Android package leaves this origin empty, so live native lookup is unavailable; saved weather still works offline.

The HTTP surface is `GET /api/v1/weather/status`, `GET /api/v1/weather/places?q=…`, and `GET /api/v1/weather/forecast?placeId=…`. Search returns at most five places. Unknown actions, extra/duplicate parameters, request bodies, malformed IDs and unsupported browser origins are rejected before provider access. Callers cannot supply a URL, host, API key, coordinates or trip context. JSON responses have `no-store` and no referrer policy; the service worker bypasses all API responses. There is no server disk cache, request log, automatic polling or saved failure presented as a new forecast. Operators should keep reverse-proxy query logging disabled for these paths.

Upstream redirects are refused, streamed bodies are limited to 150 kB, search times out after twelve seconds and the complete two-request forecast flow after eighteen seconds. Browser lookup has a twenty-second deadline and aborts when its workspace/context closes. Server parsing checks identities, timezone, units, date continuity, row lengths and numeric ranges. Provider calls are bounded to twenty per minute and nine hundred per day **per process**, with the existing HTTP request gate shared with carrier lookup. Restarting a process resets that counter; multi-instance or higher-volume deployments need an operator-managed shared quota and the applicable provider entitlement. No retry loop consumes additional calls automatically.
